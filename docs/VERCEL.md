## Deployment flow
1. Push feature branch and open PR; Vercel Git integration ordinarily creates a preview.
2. Run unit tests, typecheck and production build in GitHub Actions.
3. Test preview: upload an image, crop, save/reopen project, export PDF, verify paper size, import/export backup.
4. Merge verified PR; Vercel deploys `main` to production.
5. Verify Vercel deployment commit matches merged Git SHA, status READY, and smoke-test public URL.

## Offline service worker
`public/sw.js` is a template; after `vite build`, `scripts/build-sw.mjs` computes a unique cache revision from built HTML and precaches the corresponding hashed JS/CSS assets. Navigation uses **network-first** with a cached offline fallback; build assets use **cache-first**. No customer photos are cached by the worker: private data stays in IndexedDB.

The worker's installed precache must succeed as a unit. `/sw.js` and HTML receive revalidation headers; hashed bundles use immutable caching. A refresh while online gets the latest HTML; a future service worker version controls later navigations without silently retaining a stale shell.

Offline capability only applies after the site and assets have been successfully loaded and cached. Background AI models remain unimplemented; this is not an offline AI guarantee. Browser site-data clearing can erase projects and caches; use project backup export.

## Security and restrictions
- No required backend, cloud account, or photo upload endpoint.
- Client-side Blob processing and PDF generation.
- Do not move customer data to serverless endpoints without a separate privacy/design decision.
- Hosted origin affects IndexedDB isolation: data from `localhost` or another Vercel alias does not automatically appear at the production domain.
- HTTPS is required for production service workers.
- SSO/Deployment Protection may restrict autogenerated previews. Test the public domain separately.

## Release checks
- `npm test`, `npm run typecheck`, `npm run build`
- `dist/index.html`, `dist/sw.js`, and all referenced hashed assets exist
- service worker cache key changes when the built HTML changes
- page loads successfully at HTTPS origin; `manifest.webmanifest` and `sw.js` served with correct MIME
- confirm published commit and production alias
- online/offline refresh, project reopen, PDF export, no network photo uploads

No custom domain, database integration, Vercel environment secret or production token is needed for this static web app.
